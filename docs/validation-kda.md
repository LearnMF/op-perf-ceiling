# KDA 上限对已优化实现的核对（flash-train mk3，gfx936 / gfx938）

> 尺子：两张卡各自优化到当前较好版本的手写 KDA——`LearnMF/flash-train` 分支 `feat/kda-gfx936-mk3`（30197cc，BW1000 / bw52）
> 与 `feat/kda-gfx938-mk3`（7ef6f0b，BW1102 / nmz5）。各自在卡上从源码编译（装到独立目录，不动容器环境），
> `bench/kda_bench.py` 测 fwd+bwd 的设备时间（torch.profiler，所有 kernel 求和），27 个形状：T = 1K–32K × H = 64/32/16/8，
> 外加 K3 TP8 的 H = 12（T = 8K / 16K / 32K）。B = 1，K = V = 128，K3 门控，与 flash-train 自带基准同口径。
>
> 复现：`python -m opceil check --machine machines/gfx936-bw1000.json --measured data/measured/kda_bf16_gfx936-bw1000_20261113_mk3-30197cc.jsonl --other machines/gfx938-bw1102.json:data/measured/kda_bf16_gfx938-bw1102_20261113_mk3-7ef6f0b.jsonl`
> 完整表：`reports/kda_*.check.md`。

## 1. 结果

| | gfx936 / BW1000 | gfx938 / BW1102 |
|---|---:|---:|
| 任一层下限高于实测（违例） | 0 / 27 | 0 / 27 |
| `T_bound` / 实测，中位 | 0.07 | 0.09 |
| `T_theory` / 实测，中位 | 0.12 | 0.09 |
| **`T_split`（生产拆法 p82）/ 实测，中位** | **0.56** | **0.48** |
| 拆分搜索最优 `T_split` / 实测，中位 | 0.46 | 0.40 |
| 形状排序一致性（Spearman，p82） | 0.989 | 0.996 |

即：**已优化的 mk3 用了 p82 拆分下限的 1.8 倍（gfx936）/ 2.1 倍（gfx938）时间**。把 `T_split` 直接当预测，误差中位 44% / 52%，而且总是偏乐观。

## 2. 差距在哪：逐 kernel

p82 的 8 个 kernel 与实现它们的 mk3 kernel 一一对应（mk3 共 12 个 kernel，设备时间 100% 对上），预测 / 实测的中位：

| p82 kernel | 主要工作 | gfx936 | gfx938 |
|---|---|---:|---:|
| head_gate | 逐元素门控（流式） | 0.77 | 0.79 |
| dav | 一次三角乘积 + 流式 | 0.80 | 0.61 |
| bwd_tail | 逐元素反向 + 归约（流式） | 0.71 | 0.75 |
| wu | 重算 W/U（中等） | 0.70 | 0.62 |
| fwd_h_o | 前向 chunk 递推（scan） | 0.55 | 0.46 |
| dhu_bn | 反向 chunk 递推（scan） | 0.50 | 0.50 |
| wy_s4_split | 大量三角 / 方阵小乘积 | 0.50 | 0.37 |
| fwd_prep | l2norm + 门控 + 三角求逆 + WY（mk3 拆成 2 个 kernel） | 0.46 | 0.38 |

模型把这 8 个 kernel **全部**判为 HBM 受限。实测：
- **流式 kernel 离下限 0.6–0.8**，和 GEMM 访存受限一侧的情况一致，说明字节数和带宽这一层是对的；
- **以小三角乘积、递推、三角求逆为主的 kernel 只到 0.37–0.55**：它们实际被 64×64 chunk 内的小 MMAC、依赖链、LDS 往返和 VALU 卡住。
  这正是方法论里「满载下限 `T_full`」那一层（要按真实指令流计价），本工具按设计不做，所以这部分差距是**预期内的缺项**，不是 mk3 还有 2 倍空间。
  另一个佐证：mk3 的 fwd_prep 实际拆成了两个 kernel，而模型认为一个 kernel 放得下——片上容量估计也偏乐观。
- gfx938 比 gfx936 差：gfx938 的机器文件没有任何按 KDA 实测的 `structural` 常数（递推步长、tile 效率），只能用通用下限。

## 3. 校准之后：能到多准

`T_split` 的排序几乎完全对（Spearman 0.99），偏差主要是每类 kernel 一个稳定的比例。用「每个 p82 kernel 的 预测/实测 比值 η」做一次校准（calibrated 类）：

| 校准方式 | gfx936 误差 中位 / 平均 / 最大 | gfx938 误差 中位 / 平均 / 最大 |
|---|---|---|
| 不校准（原始 `T_split`） | 43.8% / 44.9% / 60.9% | 51.9% / 54.4% / 73.2% |
| **用另一张卡的 η**（新硬件场景：在 A 卡标定，预测 B 卡） | **18.1% / 17.9% / 35.1%** | **15.6% / 19.9% / 52.6%** |
| 同一张卡、留一个形状（同卡新形状场景） | 5.5% / 8.7% / 31.3% | 6.8% / 9.9% / 44.4% |

同卡留一法的最大误差都来自最小的 3 个形状（T·H ≤ 16K，总时间 < 0.7 ms：12 个 kernel 的固定开销没进模型）；去掉它们后中位 5.0% / 6.5%，最大 15.7% / 20.0%。

## 4. 读法

1. **下限可靠**：三层下限在两张卡、27 个形状上都没有被打破。
2. **不校准时，KDA 的绝对值不能用**：拆分下限只解释了 mk3 耗时的一半左右，另一半在 kernel 内部的指令级开销里。
3. **形状之间的相对关系非常准**：Spearman 0.99；同卡标定一次后，新形状的误差中位约 5–7%。
4. **跨卡**（在一张卡上标定、预测另一张）误差中位 15–18%：已经比「S2200 = 83% × S2000」这种整体折算有依据，但还不到 10% 以内。
   原因是不同 kernel 在两张卡上的 η 变化不一致（例如 wy_s4 从 0.50 降到 0.37，dav 从 0.80 降到 0.61），而现在没有能解释这种差别的项。

## 5. 其它两个候选算子（issue #9 DSA、#29 GDN）现状

- **DSA**（sparse_attn fwd/bwd）：flash-train 里只有 open 的 PR #40（BF16 `sparse_attn_bwd` **baseline**），没有优化实现，只能检验「下限不被打破」，不能当尺子量误差；本工具也还没有 DSA 插件。
- **GDN**：flash-train 里没有 HCU 实现。GDN 与 KDA 同族（门控从逐通道衰减换成逐 head 标量），可以由 KDA 插件改出；能当尺子的只有 FLA 的 Triton 版本（容器里有 fla 0.5.2），它本身没有在 HCU 上优化过。
