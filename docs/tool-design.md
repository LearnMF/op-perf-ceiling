# 算子性能上限预测：工具该怎么做（基于 2026-11-13 的全部验证）

## 1. 验证得到的事实（决定设计）

| 场景 | 输入 | 误差中位 | 出处 |
|---|---|---:|---|
| 只有算子公式 + 硬件规格 | shape + 机器文件 | 简单算子 10–25%，复杂算子约 2 倍；下限从未被打破 | validation-gemm / kda |
| 加上目标硬件上**同族** 3 个锚点 | + 锚点实测 / 仿真 | 约 11%（GEMM） | validation-anchors |
| 目标硬件上**同族**锚点比例换算 | + 参考卡实测 | 5–12%（FLA KDA/GDN、PV 的 DSA/MoE） | validation-transfer / anchors |
| 用**别的算子族**的锚点换算 | | 22–24%（≈ 不换算） | validation-anchors |
| 本工具的模型比例做跨卡换算 | | 26–35%（瓶颈判错时方向就偏） | validation-transfer |
| 同卡、已有打磨到位的实现，预测新 shape | | 5–7% | validation-kda |

三条设计原则由此而来：

1. **数字只能来自确定性的计算和实测**：下限、工作量、换算都要可复现、可回归测试。
2. **精度来自「同族锚点」，不来自更细的公式**：给每个算子写 800 行 L1 模型（KDA）仍差 2 倍；同族 3 个锚点就能到 10% 级。
3. **最容易出错的是判断，而不是计算**：这次踩到的坑几乎都不是公式问题——
   gfx938 驱动报错总线位宽（理论带宽 56 GB/s）、实测峰值被库 kernel 超过、T_bound 混用手册/实测口径的巧合、
   p82 拆法与 mk3 不符、BW1000 profile 里 530 us 的计时地板、MoE 两卡 EP 不同且口径未确认（归一化后误差从 22% 变 51%）、
   新算子该归哪个族、该选哪些锚点。固定脚本会把这些静默地算成错数字。

## 2. 结论：确定性内核 + AI 驱动的工作流，两层都要

### 内核（Python 包 `opceil`，确定性，有测试）—— 只负责「算」和「测」
| 模块 | 作用 | 现状 |
|---|---|---|
| 机器文件 + `calibrate` | 已有卡的峰值、延迟、曲线；未知卡按同格式填（规格 / SOC 仿真） | 有 |
| 工作量：插件 / `trace`（torch meta） | 算法必需的计算量、字节、串行结构 | 有（GEMM / attention / elementwise / KDA；torch 自动） |
| 求解：`predict`（T_bound / T_theory，项分类）、`tiling`、`capacity` | 下限与瓶颈方向 | 有 |
| 测量：`bench/*` | 在 gfx936 / gfx938 上跑开源或自研实现，kernel 级计时 | 有（GEMM / KDA / FLA） |
| 换算：`transfer`、`anchors` | 同族锚点比例、锚点 → 有效机器 → L0 铺开 | 有（实验版） |
| 核对：`check` + 回归测试 | 下限不被打破、误差台账 | 有 |
| **锚点 / 族库（待建）** | 每条记录：算子族、实现、卡、shape、实测、成熟度、口径、来源 | 现在散在 `data/measured/` |

### 工作流（AI 驱动，建议做成 skill）—— 负责「判断」和「编排」，不自己编数字
1. **理解新算子**：读论文 / 参考实现，判断属于哪个族（GEMM 类、attention 类、chunk 递推类、MoE 类……），
   用 `trace` 或起草插件得到 L0 工作量，并和 torch 自动推导交叉核对。
2. **定参考实现与锚点**：在 gfx936 / gfx938 上跑哪个开源实现；目标硬件上需要哪几个同族锚点（向 SOC 仿真 / 样片要哪些 shape）。
3. **查口径**：每份锚点数据的 dtype、是否含通信、token 是全局还是每卡、并行配置；不清楚就停下来问人。
4. **调用内核计算**：下限、换算、误差台账，全部由 `opceil` 命令产出。
5. **出报告**：下限 + 预期区间 + 误差档位（按上表「有什么输入就站在哪一级」），列出假设和未确认的口径。
6. **回写**：新测到的实测 / 锚点进库，供下一个算子用；判停时用下限和同族成熟度比例。

### 不再做的
- 为每个新算子写 L1 精细模型（只保留 GEMM 这类可复用的分块模型）；
- 用模型比例做跨卡换算；
- 承诺「只给硬件参数就能低误差预测优化上限」。
